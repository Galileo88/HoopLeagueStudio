# Roster editor data

The roster editor preserves Hoop Land's player objects when editing or moving players. A move changes `tid` to the destination team's ID and updates `contract.tid` when the contract was tied to the source team. Player ID, game history, and the rest of the player record remain intact. The source team's starting lineup drops a reference to the moved player when it contains that player's ID.

The installed Steam build's `data.unity3d` includes a readable `archetypes` text asset. Its ordered rows supply the archetype names shown in Manage Roster. IDs 1–10 correspond to those archetype rows; 0 means none. The skill code choices are the codes found across the repository's ten Pro and College templates. The full skill names were checked against the installed build's IL2CPP metadata and the developer's skill list. The editor displays names while preserving the original codes in exported league data. Imported skill codes outside that list remain selectable and preserved.

Skill descriptions are brief paraphrases of the developer's [original skill list](https://www.reddit.com/r/HoopLand/comments/1g6svd1/update_version_108_final_preview/) and [later defensive skill notes](https://www.reddit.com/r/HoopLand/comments/1hnt7qt/update_version_1084_preview_contested_rebounds/), with current names checked against the installed game. They describe the effect, not the numeric strength or unlock requirements. Imported skills without a known description show a neutral fallback.

The appearance editor changes the game's original `appearance` and per-uniform `accessories` fields. Its animated preview uses head, hair, facial-hair, eye, and idle-body textures extracted from the installed Steam build. The preview approximates the game's shader-based skin and uniform tinting; exported values remain the original Hoop Land fields.

In the bundled Pro and College templates, each attribute stores `[current, potential cap]` on a 0–20 scale. Player `pot` is a separate overall potential value; the template range tops out at 10. Strength, speed, and stamina are stored as `[0, 0]` in these templates, so those raw fields should not be read as their displayed physical ratings. The four `accessories` entries correspond by array index to the team's four `uniforms`: 0 Home, 1 Road, 2 Alt 1, 3 Alt 2. Matching `PRI`/`SEC`/`TER` accessory colors and uniform colors in the shipped teams reinforce that mapping. The four buttons beneath the player preview select both the displayed uniform and the accessory record being edited. Accessory color controls offer those team-color references, a custom color picker, and direct hex entry; only the selected uniform's accessory record changes.

League Configuration's inline Free Agents roster sits between Simulation Sliders and Retired Numbers. Its list has Add Player at the top. Add Player clones the sanitized rookie schema in `data/player-blueprint.json` into a temporary draft in the adjacent editor. Only Create Free Agent allocates a unique person ID, assigns no team (`tid: 0`), and appends the edited draft to `freeAgents`. Existing free agents remain selectable for editing or moving onto a team without leaving League Configuration. Letter logos are previews made from the installed game's letter textures and team colors; they do not replace `logoURL` in exports.

The player and team star formulas have now been traced from the installed compiled game and checked against isolated execution of its rating methods; see [Star ratings](ratings.md). These use league-editor attributes and saved lineup positions. Franchise modifiers, scouting visibility, and automatic lineup changes after import are outside this calculation. Skill effects are not simulated.
